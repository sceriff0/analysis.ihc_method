Starting data and notation

Membership is decided geometrically, from the pathologist’s own polygons — and in this export, from the polygon belonging to the same region as the cell file it scores.

Phenotypes here are FlowPath’s, from the QuPath gate tree. A companion page ran the identical analysis on cells MIRAGE phenotyped itself — same slides, same polygons, so the two differed by the phenotyping method alone — but it is withdrawn for now and FlowPath is the only phenotyping on the site.

Every value below is derived from three inputs:

  • ihc_data — single cells from the all-slide export, data/all_slide/csv/<patient>/<patient>_<A|B|C>.csv: one csv per annotation region, each covering the whole slide. ihc_data is the de-duplicated union of a patient’s region files (one row per physical cell), so cohort-level fractions are not computed over an inflated denominator. Carries phenotype, per-marker sign columns, centroids and patient_id.
  • neoplastic_data — the pathologist’s neoplastic-cellularity percentage, one row per scored region (ANNOTATION_1..3, or whole_slide for a patient with no annotation drawn). Long rather than wide, because a whole-slide score cannot be put in an ANNOTATION_k column without claiming a region that was never drawn.
  • clinical_data — the clinical CRF (HOT score, Immuno-phenotype, blood counts, RESPONSE, OS/PFS).

Membership (which cells count as “inside the tumour annotation”):

PER REGION (patient HAS an annotation directory):
  cell is INSIDE  = its centroid falls in THAT REGION'S polygon (sf point-in-polygon),
                    centroids mapped to the geojson pixel frame by
                    x_px = centroid_x / 0.325  (0.325 microns/pixel)
  union           = inside the dissolved union of the patient's polygons, scored on
                    the DE-DUPLICATED slide so a cell in two regions counts once

WHOLE SLIDE (patient has NO annotation directory):
  every cell is INSIDE — the layout's own convention, not a fallback guess

The source column on every row records which applied (sf or whole_slide). Region A is ANNOTATION_1, B is ANNOTATION_2 and so on by alphabet position, so the regions line up with neoplastic_data’s ANNOTATION_1..3 columns.

Because a polygon is read, area_mm2 and every dens_*_per_mm2 column carry real values — except for a whole-slide patient, which has no polygon and therefore no area.

Membership counts

For a set of cells (either one annotation’s inside cells or the union inside cells), region_ratios() returns:

n_inside          = number of cells in the set
n_inside_clean    = cells in the set after dropping Outlier == TRUE and
                    Unknown-phenotype cells (QC-filtered denominator)
n_tumor_inside    = tumour cells in the set
n_tumor_clean     = tumour cells in the set that survive the same clean filter
n_cd45_inside     = CD45+ cells in the set
n_cd3cd45_inside  = CD45+ AND CD3+ cells (marker-gated T cells)
n_gzmb_nk_inside  = NK-lineage cells that are GZMB+ (cytotoxic/activated NK)
n_<lineage>       = cells in the set with that lineage
                    (lineage in: CD8T, CD4T, Treg, NK, Immune_other, Stroma)

tumor_over_inside       = n_tumor_inside / n_inside
tumor_over_inside_clean = n_tumor_clean  / n_inside_clean  (outliers + Unknown removed)
cd45_over_inside    = n_cd45_inside    / n_inside
cd3cd45_over_inside = n_cd3cd45_inside / n_inside
cd3cd45_over_cd45   = n_cd3cd45_inside / n_cd45_inside   (T cells among immune)
gzmb_nk_over_inside = n_gzmb_nk_inside / n_inside
gzmb_nk_over_nk     = n_gzmb_nk_inside / n_NK            (GZMB+ fraction of NK)
frac_<lineage>      = n_<lineage>      / n_inside

Any fraction with a zero denominator is NA. The marker-gated subsets read the marker sign columns via marker_pos(), not the phenotype label; a marker the export never gated contributes no cells rather than aborting the report.

Tumour content — IHC vs pathologist

The IHC tumour metric is shown under three normalizations, all restricted to the cells inside the annotation:

tumor_over_inside       = (tumour cells inside) / (all cells inside)     -> 0..1
tumor_over_inside_clean = (tumour cells inside) / (cells inside)  -> 0..1
                          with the cell set first cleaned: FlowPath Outlier == TRUE
                          cells and Unknown-phenotype cells dropped from BOTH the
                          numerator and the denominator (a QC-filtered version of
                          tumor_over_inside; if a csv has no `Outlier` column no cell
                          is treated as an outlier)
tumor_over_cd45         = (tumour cells inside) / (CD45+ cells inside)   -> can exceed 1
dens_tumor_per_mm2      = (tumour cells inside) / (annotation area in mm^2)
                          area_mm2 = polygon pixel area * 0.325^2 / 1e6

pathologist (per annotation) = path_pct / 100, per scored region
pathologist (union)          = mean of that patient's scored-region values / 100

tumor_over_inside_clean answers the same IHC-vs-pathologist question as tumor_over_inside but removes debris/segmentation outliers and unclassified cells that dilute the denominator, so it is expected to track the pathologist’s tumour fraction more closely.

dens_tumor_per_mm2 is the same tumour-cell density (cells/mm²) that periphery reports, computed here inside the whole annotation. It needs the polygon area, so it exists only where a polygon was read:

it is defined for every patient with a geojson and NA for the fallback ones.

Being a density rather than a 0..1 fraction, it is compared to the pathologist by rank (Spearman/Kendall), not the x=y line.

Each normalization is computed both per-annotation (one polygon) and over the union of a patient’s polygons.

Concordance statistics. paired_cor3(x, y) reports three correlations between IHC and pathologist across the shared patients, each NA when n < 3 or either vector is constant:

Pearson r    = linear correlation
Spearman rho = rank correlation (monotonic, robust to outliers)
Kendall tau  = rank concordance (pairwise, best-behaved at small n)
# `metric` selects the IHC normalization; `unit_scale` draws the x=y line and forces
# a 0..1 square (only meaningful for tumor_over_inside — tumor_over_cd45 is unbounded
# and pathologist is 0..1, so their scatter is judged by RANK, not the diagonal).
# Points are coloured by `patient_id` (from cc_ann / cc_union) so a single patient's
# annotations read as one colour — useful in the per-annotation panel where a patient
# contributes several points.
plot_concordance <- function(df, metric, subtitle, xlab, unit_scale = TRUE) {
  d  <- dplyr::filter(df, is.finite(.data[[metric]]), is.finite(path_frac))
  cc <- paired_cor3(d[[metric]], d$path_frac)   # Pearson + Spearman + Kendall
  p <- ggplot(d, aes(.data[[metric]], path_frac)) +
    geom_point(aes(colour = patient_id), alpha = 0.7, size = 2) +
    annotate("text", x = -Inf, y = Inf, hjust = -0.05, vjust = 1.2,
             label = sprintf("Pearson r = %.2f\nSpearman rho = %.2f\nKendall tau = %.2f\n(n = %d)",
                             cc$pearson, cc$spearman, cc$kendall, cc$n)) +
    labs(title = "Neoplastic cellularity: IHC vs pathologist", subtitle = subtitle,
         x = xlab, y = "Pathologist tumour fraction", colour = "Patient")
  if (unit_scale)
    p <- p + geom_abline(slope = 1, linetype = "dashed", colour = REF_LINE) +
             coord_equal(xlim = c(0, 1), ylim = c(0, 1))
  p
}

Aggregation strategy — how collapsing the annotations moves the answer

The concordance panels above compare neoplastic cellularity at two fixed levels: per annotation (one point per ANNOTATION_k) and union (one point per patient). The union level hides a choice, because a patient with several annotations has several IHC values and several pathologist values, and each side has to be collapsed to one number before they can be paired. That collapse is not neutral.

The mismatch this section exists to expose. The union pair above collapses the two sides by different rules:

pathologist   path_union      = mean(ANNOTATION_k / 100)          UNWEIGHTED mean
IHC           ihc_tumor_union = tumour cells / all cells,
                                over the POOLED cells of every
                                annotation of that patient        CELL-WEIGHTED mean

For a patient whose annotations differ in size these are different summaries of the same slide. Take two annotations, 40 000 cells at 80% tumour and 4 000 cells at 50%: the cell-weighted IHC value is 0.77 while the unweighted pathologist value is 0.65. That 0.12 gap is aggregation artefact, not IHC-vs-pathologist disagreement — and the existing union panels cannot tell the two apart.

So below, every IHC aggregator is paired against every pathologist aggregator:

IHC side (per patient)
  pooled      cells of every annotation pooled and deduped, ratio recomputed
              (exactly what the union panels above use)          cell-weighted
  wmean_ann   per-annotation fractions averaged, weights = that annotation's
              cell count                                          cell-weighted
  mean_ann    per-annotation fractions averaged, every annotation equal
  median_ann  median of the per-annotation fractions (only differs from mean_ann
              at 3+ annotations)

pathologist side (per patient)
  wmean_cells ANNOTATION_k scores averaged, weights = that annotation's IHC cell
              count — the pathologist analogue of pooling cells   cell-weighted
  mean        plain mean over the patient's annotations (used by the union panels)
  median      median over the annotations
  max         the highest-scoring annotation ("worst area governs")
  min         the lowest-scoring annotation (most conservative)

The weight is always the denominator of the metric being aggregated: n_inside for tumor_over_inside, n_inside_clean for tumor_over_inside_clean. Weighting a clean-set metric by the unclean count would over-weight annotations whose cells were mostly discarded as outliers or Unknown.

One consequence to watch in the tables: a patient whose IHC region is labelled "csv" rather than an ANNOTATION_k cannot be matched to a per-annotation pathologist score, so it contributes no weight and drops out of the wmean_cells rows while still appearing in the mean / median / max / min ones. That is why n is printed on every row of the grid — compare rows only at equal n.

Only two of the twenty combinations weight both sides the same way — (pooled, wmean_cells) and (mean_ann, mean). Those are the pairs whose gap is interpretable as genuine disagreement; everywhere else part of the gap is the aggregation mismatch. They are shaded in the scatter grids and boxed in the heatmap.

A built-in check. wmean_ann should reproduce pooled almost exactly, since pooling cells is cell-weighting them. The only thing separating those two rows is the union’s dedup of cells falling inside two overlapping annotations — so a visible gap between them is a measurement of annotation overlap, not an aggregation error. Read those two rows against each other before trusting anything else here.

Recommendation

For method validation, prefer the per-annotation level over any aggregation. The pathologist reports one score per annotation, so the annotation — not the patient — is the natural unit at which the two methods can be compared like for like. It also uses every observation instead of averaging most of them away, which matters at this sample size. Aggregation is a compromise made necessary by the clinical joins (survival, response, blood counts), which are per patient.

When a patient-level number is required, use a matched pair. Reporting a cell-weighted IHC value against an unweighted pathologist value — what the union panels currently do — mixes a real effect with an artefact. Of the two matched options:

  • (mean_ann, mean) — treats each annotation as one observation on both sides. Preferred as the primary: it mirrors how the pathologist’s own numbers are produced (a per-region score, not a cell census), and one very large annotation cannot dominate the patient’s value.
  • (pooled, wmean_cells) — treats the patient’s tissue as a single specimen and asks what fraction of its cells are neoplastic. Report alongside as the sensitivity analysis. It is the more natural quantity if the annotations are arbitrary subdivisions of one tumour rather than distinct regions.

If those two disagree materially, the disagreement is itself the finding: it means the patient’s annotations are heterogeneous in both size and tumour content, and no single patient-level number represents that slide well.

Survival

group(p) = "high" if ihc_immune_score(p) >= median, else "low"   -> Kaplan-Meier
HR       = exp( Cox coefficient of ihc_immune_score )            (univariable coxph)

Event coding (coerce_event): yes/dead/relapse/1 -> 1; no/alive/censored/0 -> 0. Time = OS/PFS (months); event = FOLLOW UP (death) / PERSISTENCE OR RELAPSE? (progression).

surv_cfg <- list(
  OS  = list(time = "OS",  event = "FOLLOW UP"),
  PFS = list(time = "PFS", event = "PERSISTENCE OR RELAPSE?")
)

coerce_event <- function(x) {
  if (is.numeric(x)) return(as.integer(x > 0))
  v <- tolower(trimws(as.character(x)))
  dplyr::case_when(
    v %in% c("1","yes","y","dead","death","deceased","event","relapse",
             "progression","progressed","true") ~ 1L,
    v %in% c("0","no","n","alive","ned","censored","false") ~ 0L,
    TRUE ~ NA_integer_
  )
}

run_survival <- function(cfg, label) {
  if (!requireNamespace("survival", quietly = TRUE)) {
    message("survival package not installed — skipping ", label); return(invisible())
  }
  if (!all(c(cfg$time, cfg$event) %in% names(ihc_clin))) {
    message("missing ", cfg$time, "/", cfg$event, " — skipping ", label); return(invisible())
  }
  d <- ihc_clin |>
    transmute(ihc_immune_score,
              .time  = suppressWarnings(as.numeric(.data[[cfg$time]])),
              .event = coerce_event(.data[[cfg$event]])) |>
    filter(is.finite(.time), !is.na(.event), is.finite(ihc_immune_score))
  if (nrow(d) < 5 || dplyr::n_distinct(d$.event) < 2) {
    message("too few informative rows for ", label, " (n = ", nrow(d), ")"); return(invisible())
  }
  d <- d |> mutate(immune_group = if_else(ihc_immune_score >= median(ihc_immune_score),
                                          "IHC-immune high", "IHC-immune low"))
  fit  <- survival::survfit(survival::Surv(.time, .event) ~ immune_group, data = d)
  cox  <- survival::coxph(survival::Surv(.time, .event) ~ ihc_immune_score, data = d)
  hr   <- exp(stats::coef(cox))[1]; pcox <- summary(cox)$coefficients[1, "Pr(>|z|)"]
  cat(sprintf("%s: Cox HR per unit IHC immune score = %.2f (p = %.3g, n = %d)\n",
              label, hr, pcox, nrow(d)))
  if (requireNamespace("survminer", quietly = TRUE)) {
    # survminer defaults to its own theme_survminer (grey grid, large type), which
    # would make these the only figures on the site off-style — force the house
    # theme and the house categorical palette onto it.
    print(survminer::ggsurvplot(fit, data = d, pval = TRUE, risk.table = TRUE,
                                title = paste(label, "by IHC immune score (median split)"),
                                legend.title = "", palette = unname(oi),
                                ggtheme = theme_paper())$plot)
  } else {
    plot(fit, col = c(oi[2], oi[1]), xlab = "time", ylab = "survival",
         main = paste(label, "by IHC immune score"))
    legend("topright", levels(factor(d$immune_group)),
           col = c(oi[2], oi[1]), lty = 1, bty = "n")
  }
}

  • Cohorts are small; every correlation is Spearman with its n reported. Read associations as descriptive.
