This page answers one question for every arm: which patients are in, from which files, under which membership rule — before any figure is drawn. Read it after adding a patient, moving a tree, or symlinking the share. Nothing here is an analysis; every table is a listing of what the readers in code/arms.R, code/arm_cells.R and code/load_data.R actually found.

Root searched: /hpcnfs/home/ieo7660/workflowR/ihc_method/data.

csv-only patients (FLAG_MEMBERSHIP_FILES in code/arms.R): 15370 ← flowpath/153070.csv, 36672_2 ← flowpath/36672_2.csv. Every arm reads them from that one file and ignores any copy in its own tree. No polygon in any arm and no pathologist score; membership comes from the export’s own Out_of_annotation flag, and their one region is ANNOTATION_1.

Per arm

For each arm, three tables:

  1. Tier directories — the directories the registry expects and whether each exists. A missing region tier means the arm loads nothing.
  2. Files found — every csv and geojson under those directories with the patient and region the parser read off its name. A file in the wrong place shows up here with a wrong patient_id (for instance the tier directory’s own name), which is the commonest reason a new patient “is not there”.
  3. Cells read — one row per (patient, region) actually loaded, with the cell count and the membership rule (sf polygon, flag from the export, whole_slide by the arm’s convention), followed by the union rows.
